# 项目协调与工程执行

本轮按 2026-09-17 发布的新版 Claude Projects 重新划分产品，而非沿用旧版“文件夹内多个独立聊天”。官方资料：[Projects redesigned](https://claude.com/resources/articles/projects-redesigned)。用户提供截图作为布局和交互证据；截图中其他项目的内容不作为本系统需求、权限或数据。

## 对应关系

| 参照交互 | 本地工程工作台 |
|---|---|
| 一个持续项目会话 | 项目 coordinator 主对话；承接需求变化、问题与工作结果 |
| 按任务创建独立 thread | worker 独立上下文与运行记录；可单独追加要求、停止、重新打开 |
| 主会话里的任务引用 | 可打开右侧任务面板的引用；不离开主会话 |
| Overview 按状态组织 | 等待审批、工作中、排队、待查看、已解决 |
| Library | 项目资料、模型、仿真输出及分析文件 |
| 共享记忆 | 项目显式 memory 和版本；与任务全部过程日志区分 |

并发是资源设置，任务数量不固定为三。主协调者按需要启动或复用任务；并发不足时排队。任务预算、时间与模型调用量仍必须可配置和可见，避免把“可派任意任务”理解成不受控制地无限运行。

主对话默认占据工作区；模型图、结果、工程工具和设置按需打开。页面仅保留操作所需标签和状态，方法说明放在文档，不作为首页宣传内容。

## MBSE 执行边界

协调对象是系统工程工作，而不只是写文档：场景、需求、架构、机理模型、仿真、约束检查和证据应通过稳定 ID、版本及参数关联。各阶段实际使用的工具可不同。

API/CLI 适合重复求解、参数扫描及工件导出；computer use 适合操作只有图形界面或当前操作需要图形交互的工具。两种路径共享任务及结果记录。工程软件是否安装、许可证与模型有效域应如实记录。

当前新增的本地仿真工作面连接实际数值求解器；它不是 Capella、SysML 编译器或完整商业仿真套件。其结果只支持声明模型与参数范围内的分析，不代替上游项目复现、HIL 或实物校准。
