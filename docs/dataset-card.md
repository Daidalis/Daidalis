# 真实工程问题题库 v1

这是 **来源已核对、执行尚未复现** 的初版任务目录。含 13 个真实 issue、4 个工程项目。它让用户浏览并导入具体工程问题，不能作为已验证 benchmark 或模型能力排行榜。

## 内容与适用范围

题目从 NASA NOS3、PX4、ArduPilot 和 Bitcraze Crazyflie 的官方 issue 选取。项目是真实工程项目；问题可能是历史 bug、当前开放调查、功能提案或需求歧义。数据集没有把所有 issue 都叫做实物故障，也没有把开放提案当已批准规范。

NOS3 源于实际 STF-1 飞行项目；今天的 STF design reference mission 是 generic 参考实现。二者不能混同。参考任务的需求不完整，不构成真实 STF-1 的完整系统模型或已校准数字孪生。

## 文件与公开边界

- `datasets/real-issues.v1.json`：公开目录；题干、输入需求、交付、拟定 gate、环境、限制与来源。
- `datasets/evaluator/answers.v1.json`：仅评测方使用；历史诊断、关联变更和不确定性。公共 API 不得返回它，也不得把它自动拷入 agent 工作区。
- `datasets/README.md`：字段约定与使用步骤。
- `datasets/validate.mjs`：只验证题库结构、数量和公开/答案分离标记；不运行工程任务。

publicPrompt 使用中文重新表述症状和任务，不给出历史根因或具体补丁。验收要求表达期望行为而不是强制复刻一个历史实现。来源链接仍可通向完整讨论，因此当前版本不能称盲测。

## 证据等级

`evidenceLevel = source-verified` 只表示编者阅读了项目官方页面，核对题目存在、症状/需求与当时状态。不是独立证实报告内容，也不是复现问题。

所有原生任务均为 `executionStatus = not-reproduced`、`baselineCommit = null`。没有已冻结的上游源代码题包、依赖镜像或原生隐藏行为测试。`gates[].status = planned-not-executed`。任何 UI 都应同时展示来源证据和执行状态，避免只用“已验证”三个字。

`nos3-351` 另附编者新增的 `quaternion-interface-v1` 纯声明式接口子评测：xyzw Hamilton，输入 q_IS（sensor-to-inertial）和 q_BS（sensor-to-body），输出 q_IB（body-to-inertial）。它使用独立旋转矩阵 oracle 检查接口语义，scope 为 `interface-contract-only`、`upstreamReproduction = false`。通过该子评测不能计作复现或修复 NOS3，也不能提升原生任务的 executionStatus。

官方 issue 关闭不等于已有经过本数据集核验的正确补丁。evaluator 仅保留可追溯的历史线索，`goldenPatchAvailable = false`。开放题尤其不能通过“与历史补丁一样”来评分。

## 形成正式评测的步骤

1. 评测方选择可复现版本，锁定主仓库、所有子模块、工具链、镜像、输入与 SHA-256；历史题需修复前基线。当前 null 必须替换或任务保持 blocked。
2. 制作剥离根因、讨论、修复和 git 历史的 agent 输入快照。仓库的 AGENTS/贡献要求仍须按执行环境处理，源内容不得成为高于用户的指令。
3. 把 evaluator、参考补丁、隐藏种子与测试放在 agent 不可访问的隔离位置；禁用或限制网络，避免访问原始 issue/PR。单纯藏起一个 UI 标签不能隔离答案。
4. 先由独立维护者验证故障复现、已知参考/合理方案，以及 no-op 和明显错误方案；区分规范歧义。开放政策题先批准决策表，否则相应 gate 为 blocked-policy。
5. 为每个拟定 gate 实现可重放检查，固定数值公差、延迟预算、工况、重复次数与失败判据。保留 fail-to-pass 及 pass-to-pass 数据和原始日志。
6. 记录 agent 提交、工具轨迹、资源/时间成本；独立运行隐藏检查。报告逐 gate 的 pass/fail/not-run/blocked，不能把 not-run 计入通过。
7. 软件、HIL、实物/飞行层分别报告。缺硬件不阻止早期建模，但禁止把软件替身结果当原始设备修复或产品认证。

G0 检查基线可重建，G1 检查场景/模型/追溯，后续 gate 检查各题行为。它们是建议的验收合同，不是已经存在的上游测试集。编者追加的边界/回归要求由 `curatorAdditions` 单独标注；`upstreamFacts` 保留可公开的源事实。

## MBSE 的评估边界

仅能修代码不够：任务要求场景与可测需求、接口/结构/行为模型、变更影响和需求到验证的关联。仅能生成模型也不够：行为 gate 必须实际执行。文件完整性评分只能说明交付完整，不能解释为系统正确率。

即使未来这些题全部通过，也只支持这些版本、工况和选定工程活动；不能证明自动发现所有利益相关方与风险、设计任意物理产品或替代实物试验。题库偏向有公开代码与可模拟接口的航天/无人机系统，不能代表工业 MBSE 全域。

## 来源、复用与局限

每题 `sources` 给出一手链接，`sourceNotes` 保存核对日期和摘要。具体历史解法存放在 evaluator。这里没有镜像整页 issue、第三方日志、供应商手册或 CCSDS 标准正文；源许可证仍各自适用。本数据集的中文任务设计不转移上游内容权利。

局限：选题与摘要由单一编者完成；无双人标注一致性、随机抽样或覆盖率证明；公开问题有训练污染和链接答案泄漏；旧版本可能失效；报告者参数/硬件可能不全。后续应按任务级版本和复现记录升级证据状态，而不是用“真实项目”替代验证。
