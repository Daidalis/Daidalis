# 第一项工程任务：从需求到可检查的结果

先运行应用，再按任务需要连接 Agent 和专业工具。这个例子是一项载荷温控方案分析，不能等同真实卫星设计、标定或放行。应用启动、模型推理、数值求解和工程验收分别检查。

## 启动并连接 Agent

按照[安装说明](installation.md)运行 `npm ci`、`npm run doctor` 和 `npm start`，打开 http://127.0.0.1:4317 。应用启动不需要先安装 Python 数值扩展或 VM。

在「设置 → 模型与 API」配置并测试 Codex 或 Claude Code，填写所选提供方支持的模型、endpoint 和密钥。Codex 需有可执行的原生 CLI；Claude 使用项目依赖中的 Agent SDK。连接表单保存成功不代表模型调用成功。不要在聊天里发送密钥。

专业求解器是另一项配置。`npm ci` 不会安装 OpenModelica、NOS3 或工程 VM。先查看 doctor 与项目工具的真实状态；未配置的能力应报告缺失。完整冻结的 NOS3/42 工程环境目前尚不能仅由公开仓库一键重建，详情见[安装说明的专业执行部分](installation.md#numerical-and-professional-execution)。不要复制他人的 VM 状态或关闭哈希检查绕过准备。

## 创建工程项目

在文件系统中准备一个独立工程文件夹，再在 Manta 左侧新建项目并选择该目录。不要选 Manta 源码或服务数据目录。你也可以选择已有工程，让 Agent 先识别当前需求、模型、代码与缺口，而非强制重新开始。

在 Coordinator 主聊天发送：

```text
开发一个载荷温控方案。载荷温度应保持在 20–30 °C，
稳态阶段跟踪误差不超过 1 K，环境扰动后温度为 -20 °C。
比较加热器最大功率 10 W 和 30 W 的方案。

先明确需要我决定的边界、参数来源和模型假设，再建立需求与
设计模型，用已配置且适合这项任务的真实工具执行分析。
保留失败结果，给出温度、误差、能耗和约束满足情况。
未标定参数或未做试验的要求不能写成已验证。
```

这是任务需求，不是工具调用脚本。Coordinator 应解释分工和缺失条件；有可独立推进的工作时，可以委派一层平级 thread。用户仍可继续与 Coordinator 交流，或进入任一 thread 提出纠正。

如果采用旧的 `thermal-control-v1` 示例，它是声明式双节点 SciPy 热网络，并不代表 OpenModelica 或真实航天器。该可选示例需要独立的私有 Python 环境及 `MBSE_PYTHON` / `MBSE_ENGINEERING_DEPS`；安装方式与网络卷原生扩展限制见[安装说明](installation.md)。不要为了先打开应用就运行这个安装脚本。

## 观察分工、等待与交接

Coordinator 保留主聊天；右侧 Overview 用于查看 thread 状态。聊天中的任务引用可以打开该 thread，过程和工具调用属于各自的聊天，不应全部堆到 Coordinator。工具细节默认折叠，文档、模型和结果可从聊天入口打开。

你可以在 Coordinator 补充“结论中说明哪个假设最需要实测”，也可以单独进入某个 thread 修改其任务边界。运行时补充要求的送达与排队状态应明确呈现；不能将待送达消息当成已经执行。

Coordinator 需要子任务证据时等待，收到结果后复核再汇总。已结束的 thread 无需手工标记完成或手工回传，之后仍可继续聊天；新一轮运行重新打开相应任务。thread 不再创建下一级 thread。

Manual 与 Auto 的边界见[Agent 运行时](agent-runtime.md#权限与隔离)。Auto 允许配置范围内的普通操作，真正的原生审批请求、原生桌面和远端 Computer 等仍可能要求批准；它不是跳过运行时权限。模式在每轮启动时固定。

## 打开模型和真实结果

从所属聊天中的产物入口打开需求/模型、文档和仿真结果。支持的源码可以审阅或编辑；受保护的作业证据只读。修改模型或参数后，必须重新执行作业才能得到新结果，旧曲线不能代表新版本。

核对以下信息：

- 两方案有不同的运行 ID、模型版本和实际参数吗？
- 结果确实来自所声称的求解器，还是仅有文字描述？
- 温度范围、跟踪误差和能耗分别支持什么结论，哪些检查失败？
- 每项需求是否连接到模型、验证方法与对应结果？
- 未标定参数、硬件/HIL、环境和寿命验证等缺口是否仍保留？

没有已配置求解器时，Agent 可以整理候选需求、假设和模型草稿，但应明确数值验证受阻。不要将“Agent 已完成”“进程成功退出”“判据通过”和“工程被接受”合并成一个状态。

## 常见情况

| 现象 | 下一步 |
| --- | --- |
| 页面可打开，Agent 未连接 | 在设置中配置并实际测试运行时；应用可启动不代表已有模型权限 |
| Codex 可检测但测试失败 | 检查测试错误、认证和 endpoint 兼容性；自定义路径使用 `MBSE_CODEX_PATH` |
| 专业工具 unavailable | 配置该工具的隔离 runner；不能以模型自述或另一种求解器替代执行证据 |
| Coordinator 没有创建 thread | 它可能选择独自处理；未发生委派就不能声称多 Agent 协作已发生 |
| 回复有数字但没有运行证据 | 查看工具结果、作业 ID、输入和原始输出，要求明确来源 |
| 想先了解交互 | 查看[静态网站 demo 指南](demo.md)；示意对话不是现场 Agent 执行 |

后续可按[工作流](mbse-workflow.md)推进变更与复核，或在已有 NOS3 工程中提出有明确基线的增量任务。网站里的 STF 低电量历史示例覆盖限定软件链，不能代替完整 STF 的需求、任务级仿真或实物验收。
