# Manta 架构

这是绑定本机回环地址的应用：浏览器工作面连接源码目录中的 Node.js 执行器，可选 Cocoa/WKWebView 窗口作为桌面入口。可写状态默认放在项目 `data/`，也可通过 `MBSE_DATA_DIR` 配置。它不是多用户托管服务。

## 项目、主对话和独立任务

每项目有一个持久协调者主对话，以及按需要创建的工作线程。工作线程有自己的历史、运行和指导消息；共享的是项目资料、指令、记忆与工作区，不是隔离 Git 分支。工具 `start_thread/delegate_task` 入队后立即返回，不阻塞主对话等待子任务全部结束。

默认并行预算是 4 个工作线程；主 Agent 使用独立通道。默认每个起始运行最多创建 16 项任务。它们是内部执行边界，不在普通项目设置中展示。系统没有固定三角色流程，也不靠「单个 / 团队」切换改变行为。

任务完成或失败将本轮摘要、状态和产物引用写回项目协调者。有限的自动汇总默认最多恢复 2 次，每次最多 4 轮、120 秒，不能启动新任务链；用户新一轮主对话会重置该汇总预算。运行中的人工指导在工具调用边界交付。审批、取消、任务状态和模型变化均持久化为事件；进程重启会把未完成运行标为中断，不假装恢复执行。

工作线程保存带线程路径的分析和模型草稿。只有协调者可以通过带版本检查的 `update_model` 合并共享图模型，避免多个线程无审阅覆盖同一个基线。

## 界面与共享上下文

主对话常驻中间。顶栏仅有 Overview，打开按状态组织的线程，点击工作线程在右侧查看或指导。Library 汇集项目资料和产物；「工具」按需打开系统模型、工程仿真、题库、Computer 和记录。模型与 API 是左下角入口的全局设置。消息不常驻显示角色标签与时间；输入框自动增高，模型选择靠右，附件与权限靠左。

新项目绑定用户选择的现有目录，旧项目保留原工作区。目录固定、解析为真实路径并在执行时复核；项目文件夹不能指向应用源码、服务状态或系统/过宽目录。Manual 与 Auto 在每轮启动时固定，子任务继承且不能自升权限；运行中的切换仅影响下一轮。详见 README 的权限说明。

项目指令、共享记忆、模型和资料目录进入上下文。资料检索为文本关键词检索，没有暗含向量数据库或未配置云服务。导入文档、网页和截图是待审查来源，不应变成 Agent 指令。渲染模型输出时转义内容。

## 模型连接

提供 OpenAI-compatible Chat Completions、OpenAI Responses、Anthropic Messages、Ollama 与本机 Codex CLI 适配。工具循环由应用拥有；CLI 可复用正常登录，但应用不读取或提取 OAuth 凭据。密钥保留在服务端配置或环境引用中，不在 bootstrap 或连接列表返回。

适配器协议测试不证明所有兼容服务支持相同工具和图像行为。实际连接需单独测试。截图会作为真实图像输入传给支持视觉的连接；纯文本连接不能据提取文字宣称完成视觉验收。

目前 Codex CLI 是模型后端，并未完整复用原生 Agent 会话。Codex app-server 与 Claude Agent SDK 的可行接入边界见 [agent-runtime.md](agent-runtime.md)。

## 执行与权限

文件工具限定项目工作区，拒绝路径与符号链接逃逸。命令逐项审批，并要求操作系统沙箱；没有静默降级到无沙箱执行。运行受轮数、超时、取消和项目资源限制。Agent 不能批准自己的权限。

隔离浏览器默认打开当前项目工程工作面，`browser.engineering` 可直接定位。浏览器使用独立 profile、允许域名/路由、屏幕版本及截图证据。本地工程 API 限定当前项目，拒绝进入其他应用 API；远端网页操作遵循审批策略。验证链路的小型 fixture 仍是测试辅助，不能冒充工业软件操作。

原生 macOS 桌面单独启用，需要用户同意、每次操作审批及系统屏幕录制/辅助功能权限。`desktop.apps` 列出实际探测的工具，`desktop.open_app` 只能打开允许的已探测工具标识。是否已在本轮行使这些权限，以验收记录为准。

## 工程模型、求解与证据

系统图包含利益相关方、需求、场景、功能、部件、接口、风险、决策、假设、测试与证据。结构检查能发现引用和声明覆盖问题，不能证明 SysML 合规、物理准确或实际安全。

`engineering.mjs` 执行冻结的双节点热控制 ODE，通过真实 SciPy `solve_ivp` 求解、参数扫描及独立能量/解析极限检查。图形工作面直接使用运行数据；记录参数、单位、模型版本、求解器配置、软件版本、哈希、CSV 和 SVG。同项目求解排队，等待可取消，实际求解有超时。

本轮模型来自工作台声明，非上游卫星设计。专业工具目录区分可运行、缺失和未连接；没有把 SciPy 工作面当作 Capella、OpenModelica 或商业软件的验收。详细模型、接口和限制见 [mbse-workflow.md](mbse-workflow.md)。

题库把公开题干与评测方历史资料隔离。上游 issue 的初始状态是 `source-verified / not-reproduced`。交付完整性、接口子题和工程行为是不同范围；四元数独立矩阵 oracle 只验证声明式接口约定，不能升级为 NOS3/cFS/42 复现。

## 部署边界

当前为本机单用户执行器。不得仅通过公开反向代理将其变成多人服务；那需要认证、租户隔离、硬隔离与对应部署设计。模型上下文、任务结果及产物可能含工程资料，接入外部模型时由用户决定可发送范围。
